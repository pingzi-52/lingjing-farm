# 自主推进：目标引导、存档迁移与居民提示

用户已授权按优化提案自主规划并执行。本轮完成三个可独立验收的单元；保留现有本地未提交工作，不commit/push或发布。

1. 纯目标展示模型：从任务、背包、木箱、田地和作物服务推导下一步。优先级为已完成/待领取/随身可交付/田间可收获/目标作物待浇水/等待生长/木箱取出/有种子待播种/补购或等适种季节。仅目标作物参与，雨天免重复浇水；混合田地保留次要提醒。Q与HUD用相同模型，L三委托展示材料进度、状态及地点。提示不保存，不改变任务规则。
2. 标题S或点击打开存档管理。导出当前有效存档；导入文件限制256KiB，先严格校验V1–V6并显示日期/金币/版本，玩家明确确认替换。取消不写入，提交再次校验且核对预览时的原档原文。有效原档备份到backup，损坏/未来原档保留到rejected；原文超限无法备份时拒绝替换。备份失败不写主档，主档写失败仍保留原主档与可恢复备份。存储在预览后变动则拒绝覆盖。文件异步完成后必须核对菜单仍打开且未选择其他文件。成功后回标题正常继续，禁止默认新建覆盖。沿用V6，无后端。
3. 岚/阿榆驻点身体不动，头顶使用待接取/材料收集中/可交付/已完成提示；靠近时E提示与L汇总共享纯材料就绪状态。新增图片动作留下一轮，不把静态缩放冒称动画。

实机复核补强：完成后的进度显示历史“已交付×数量”，避免材料消费后出现已完成0/3。导入另存before-import原文副本，普通自动保存不会更新；存档管理增加“导出导入前备份”，通过现有预览/确认流程恢复。副本以最近一次替换已有主档为准，导入到空主档不清除已有副本。额外副本保存失败也必须阻止主档替换。

参考实现：MerchantResident的四种状态；ResidentDialogue/CraftingMenu材料计数；PausePanel暂停、焦点与关闭；SaveManager严格校验和备份；quest/exploration-session失败事务测试。代码勘察已在OPTIMIZATION_PROPOSAL附录保存。

验收：目标模型覆盖无作物、雨天、混合田、再生作物、木箱、已售/遗失种子和跨季；迁移覆盖全字段往返、V1–V5、损坏/未来/超限、备份/写入失败、预览冲突与取消；浏览器检查HUD/Q/L一致、真实交付前后居民标记、标题S输入隔离、下载与独立浏览器上传、取消不改档、错误输入不改档、导入后继续与刷新。最终完整测试/类型检查/构建及差异检查。
